# 系统演示视频：分镜与录制说明

目标时长 4–5 分钟。录屏用 OBS 或 Windows 自带的 Win+Alt+R，剪辑用剪映或必剪。

## 录制前准备

1. 显示设置：1920×1080，缩放 125%（和评估时的设置一致）。关掉通知（专注助手），任务栏只留常用图标。
2. 桌面上放 Chrome、Edge 的快捷方式；关掉所有窗口。
3. 打开一个命令行窗口，放在屏幕右侧约 1/3 宽的位置（演示时观众要能同时看到日志和被操作的窗口）。
4. 启动 Ollama（用 llava 时），先跑一遍试运行：

       python -m scripts.run_demo --dry-run

5. 正式录：

       python -m scripts.run_demo --agent llava --countdown 3

   只重录某一段：`--only 5`。

## 分镜

| 段落 | 时长 | 画面 | 旁白要点 |
|---|---|---|---|
| 0 开场 | 20s | 标题页（项目名、姓名）→ 架构图 `results/final/fig_architecture.png` | 一句话说明系统做什么：看屏幕上的文字，决定点哪里、输入什么，再检查有没有做成 |
| 1 系统命令启动 | 20s | 演示 1：“打开记事本” | 能用系统命令完成的步骤优先走命令（日志里路由显示 tool_use），不依赖桌面图标 |
| 2 搜索（两步） | 40s | 演示 2：“打开 Chrome 然后 搜索 McMaster 选课” | 指令被拆成两步；第二步规则直接找到搜索框；中文走剪贴板粘贴；输入后复查屏幕上有没有输入的内容 |
| 3 三步任务 | 40s | 演示 3：“打开 Edge 然后 搜索 天气 然后 点击 图片” | 三步串联；可以停在一帧上展示 Set-of-Mark 标注图（`som_test_result.png`） |
| 4 菜单 | 20s | 演示 4：“打开记事本 然后 点击 文件” | 点击匹配：去掉动词和噪声词后，按精确、包含、模糊三级匹配 |
| 5 快捷键 | 20s | 演示 5：“打开记事本 然后 按 Ctrl+S” | 第 8 周新增的动作，不需要找目标，直接执行（路由 direct） |
| 6 滚动 | 30s | 演示 6：“打开 Chrome 然后 搜索 天气 然后 向下滚动” | 同上；滚动作用在屏幕中央的窗口 |
| 7 容错 | 30s | 演示 7：“打开 Edge 浏览器 搜索 Edge 浏览器使用教程” | 输入内容里含应用名，旧版会误判成启动 Edge；现在只有意图是点击、关键词恰好是应用名才走系统命令 |
| 8 失败与重试 | 30s | 任选一次出现重试的日志片段（或者故意在页面没加载完时下指令） | 失败分类与重试：日志里每次尝试的失败原因、换目标、退避等待 |
| 9 结果 | 30s | 结项报告中的路由对比图、验证阈值图、第 8 周新增功能图 | 两三句话总结：规则路由 49/50、26 个故障场景全部通过、阈值和降采样有量化依据 |

## 剪辑建议

- 每段开头叠一行字幕：演示编号 + 指令原文。
- 命令行的字号调大（至少 16），录完后可以对日志区域做局部放大。
- 等待大模型和页面加载的时间可以加速 2–4 倍，并在画面角落标注“已加速”。
- 结尾放一页项目信息：代码结构、测试数量、报告名称。
